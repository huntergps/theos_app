# U03 · Clientes y productos reactivos

Se añadió una frontera UI genérica en `theos_panel/lib/features/clients/`:
`CatalogRepository<T>` expone streams locales, refresh y paginación por cursor;
`CatalogController<T>` conserva consulta, selección y borrador fuera del árbol
de widgets. `EntityPicker<T>` es reutilizable por clientes y productos, usa
Material, lista en compacto/medio y grid solo en ancho amplio (>=840), con
estados inicial/loading/data-empty/error diferenciados, contador, cursor y
errores accesibles. `ClientsScreen` y `ProductsScreen` solo reciben el puerto;
no hacen llamadas Odoo ni crean persistencia. Ambas pantallas aceptan además un
`CatalogController` creado por el scope, muestran detalle contextual adaptable
del elemento seleccionado y expresan catálogo no disponible cuando falta el
puerto, sin simular un vacío.

El test usa un fake durable compartido entre instancias para demostrar datos
offline tras reinicio; un error conserva registros/cursor. Las consultas validan
pageSize/cursor/búsqueda sin asserts; cambiar búsqueda limpia cursor, snapshots y
páginas son inmutables, y un resultado tardío de una consulta vieja se descarta.
También verifica UUID, selección y borrador tras resize y refresh, error visible
y búsqueda representativa de 5000 registros (<500 ms en la ejecución).

Verificación (Flutter 3.47.1 / Dart 3.13.1):

- `flutter analyze lib/features/clients lib/features/products test/features/catalogs` — limpio.
- `flutter test test/features/catalogs/catalog_features_test.dart` — 6 pruebas pasan.

No se tocaron router, manifests, exports, schema, dependencias Odoo ni
`theos_pos`/`fluent_ui`.
