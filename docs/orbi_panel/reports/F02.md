# F02 · Sesión, almacenamiento y credenciales

## Implementación

- `RuntimeDatabaseOwner` es dueño explícito de una única `AppDatabase` activa;
  fuerza apertura con una consulta real, reutiliza el mismo scope, cambia de
  scope cerrando antes el anterior y tiene `close` idempotente.
- El nombre Drift se deriva de `appId`, instalación, servidor, BD y usuario
  mediante SHA-256 estable de `scopeKey`; no usa codificación Base64 con pérdida
  de mayúsculas ni `DatabaseHelper` estático.
- `SessionRuntime` publica una activación solo después de abrir la base y
  conserva lease/generación y epoch para invalidar respuestas tardías y evitar
  que una activación vieja cierre o publique sobre el scope nuevo. Puede crear
  un `OdooClient` solo cuando la activación recibe API key; una activación offline
  permanece DB-only.
- `CredentialStore` namespacea referencias por scope y permite declarar
  `secureStore` o `webSessionOnly`; referencias y scope se codifican sin `/`,
  incluido `appId`, y no incluye secretos en claves ni logs.
- `InstallationIdStore` usa backend y generador inyectables, con restauración
  estable por aplicación sin singleton global.

## Credential backend

Added `SharedPreferencesInstallationIdBackend` with an injected preferences
instance and async `create()` factory. `InstallationIdStore` remains the owner
of app namespace/key derivation; no mutable singleton was introduced.

Focal test uses `SharedPreferences.setMockInitialValues` to verify restore across
new backend/store instances and isolation between `orbi-panel` and `other-app`.
