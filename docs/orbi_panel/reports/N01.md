# N01 · notification contracts

Implemented pure Dart contracts for notification entries, delivery intents,
scope/partition identity, targets, preferences, capabilities and source events.
Deduplication is semantic: entry keys use scope + partition + source; delivery
keys additionally retain revision and channel. Company and global partitions are
explicit and company IDs must match their partition exactly. Keys use canonical
JSON arrays to avoid delimiter collisions. Unsupported/denied permissions are
typed and separate; caller collections are defensively copied.

Targets contain only opaque type/reference data; no RPC, financial action,
plugin, UI, timer, Drift schema or Odoo execution exists here.

Runtime validation rejects empty identities, negative revisions/attempts, invalid
targets and mismatched scopes. Focal `dart analyze` and `dart test` pass,
including rejection, collision-like and external-mutation invariants.
