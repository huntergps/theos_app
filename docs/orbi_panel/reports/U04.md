# U04 · Órdenes y pendientes

Se añadieron `orders_contracts.dart` y `orders_screen.dart`. La UI consume un
`OrderRepository` local inyectable y reutiliza `OrderQuery`,
`CapabilitySnapshot`, `SaleOrderState`, `OperationSyncState` y `FiscalState` de
`theos_pos_core`; no contiene llamadas Odoo ni credenciales.

`OrderFilterPolicy` inicia a vendedores en `Mis ventas` (authorFilter del
usuario), permite `Todas` únicamente con `orders.view_all`, y deja al cajero
sin filtro de vendedor, con órdenes `sale` pendientes de cobro/facturación.
Lista y contador proceden del mismo `OrderSnapshot` publicado para exactamente
el mismo `OrderQuery` y company scope; `cashierPending` usa el predicado
canónico `OrderWorkQueue.cashierPending`. Cada tarjeta separa negocio, local/sync
y fiscal; filtros, carga, vacío y error son visibles y accesibles. Layout lista
compacto/medio y grid amplio Material 3.

La prueba usa órdenes y capacidades ficticias para Sebastián/vendedor y
Jacqueline/cajera. Verifica permisos, company scope, authorFilter, contador,
pendientes, error visible, respuesta tardía descartada y conservación del filtro
al refresh/redimensionar sin excepciones.

Verificación (Flutter 3.47.1 / Dart 3.13.1):

- `flutter analyze lib/features/orders test/features/orders` — limpio.
- `flutter test test/features/orders` — 6 pruebas pasan.

La composición añade `ScopeOrderRepository`, respaldado por `sale_order` local
mediante `RuntimeLocalOrderReader`, con lease activo y el mismo predicado para
lista/conteo. `/sales` ya abre `OrdersScreen`; si no hay sesión, perfil o
capacidad efectiva, muestra configuración requerida. Cashier no recibe
`authorFilter`; `Mis ventas` se mantiene seleccionable sólo cuando corresponde.
Las respuestas posteriores a cambio de scope se descartan.

Verificación adicional: `flutter analyze lib/app lib/features/orders` y
`dart analyze` del lector runtime — limpios.

El repositorio ahora intenta refresco JSON-2 usando el `SessionActivation`
actual y confirma el mismo lease antes de hacer upsert. El upsert único de
resumen conserva trabajo local `is_synced = 0`; si no hay cliente, la consulta
continúa desde `sale_order` persistente para modo offline/reinicio.
